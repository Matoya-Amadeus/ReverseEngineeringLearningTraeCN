# Live Evidence Bootstrap Notes

Date: 2026-03-18

## Purpose
This file documents the bootstrap live input used to make strict coverage gates runnable before real capture import is wired.

## Input Files
- `docs/provider-fingerprints.live.in.jsonl` (active merged live input)
- `docs/provider-fingerprints.live.real.in.jsonl` (real capture staging input)

## Current State
- `live.in` currently contains 9 `bootstrap-sample` rows (batch1+batch2).
- Live route coverage baseline is full (`9/9`), but real live coverage is still `0/9`.
- Not a replacement for production-grade real capture evidence.

## Replacement Rule
When real capture rows are available:
1. (Optional) Import HAR captures to real staging file:
   - `TRAE_AUTH_HAR_FILE=<path-to-har> TRAE_AUTH_FINGERPRINT_LIVE_IN=docs/provider-fingerprints.live.real.in.jsonl node replay/import-live-fingerprints-from-har.mjs`
2. (Optional) Append additional real rows into `provider-fingerprints.live.real.in.jsonl`.
3. Replace per-route bootstrap rows with real rows:
   - `node replay/replace-bootstrap-with-real-captures.mjs`
4. Register live captures:
   - `node replay/register-live-fingerprint-captures.mjs`
5. Rebuild evidence:
   - `node replay/analyze-fingerprint-evidence.mjs`
6. Run strict coverage gate:
   - `node tests/auth/run-live-coverage-strict-check.mjs`
7. Run strict real-live quality gate:
   - `node tests/auth/run-real-live-quality-strict-check.mjs`

## Strict Gate Defaults
- `TRAE_AUTH_REQUIRE_LIVE_COVERAGE=1`
- `TRAE_AUTH_LIVE_COVERAGE_MIN=1.0` (default in strict check runner)

## Real-Live Quality Gate
- `TRAE_AUTH_REQUIRE_REAL_LIVE_COVERAGE=1`
- `TRAE_AUTH_REAL_LIVE_COVERAGE_MIN=1.0` (default in `run-real-live-quality-strict-check`)
- This gate fails until bootstrap rows are replaced by non-bootstrap real captures.

Replace bootstrap samples with real live capture rows and keep both strict thresholds at 1.0.
